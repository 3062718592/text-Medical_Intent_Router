|---|---|---|---|---|---|

# 数据增强消融：回译（back-translation）

## 实验设计

| 项 | 设置 |
|---|---|
| 增强方法 | 中文 → 英文 → 中文回译，DeepSeek `deepseek-chat` |
| 温度 | 第 1 条变体 T=0（忠实），第 2 条起 T=1.0（制造差异） |
| 生成量 | 3490 条有效变体（原始产出 3734，质检丢弃 244） |
| 训练集 | 人工 1667 + 增强 3490 = **5157 条**（3.09×） |
| 验证集 | **416 条，全程未参与增强** |
| 标签分布 | 各类 2.83×–3.20×，无偏斜 |

## 结果

| 训练集 | 构成 | 准确率 | Macro-F1 | Weighted-F1 |
|---|---|---|---|---|
| 1667 | 人工 1667 | **0.5865** | 0.4898 | **0.5574** |
| 3196 | + 增强 1529 | 0.5793 | 0.5008 | 0.5603 |
| **5157** | + 增强 3490 | 0.5745 | **0.5123** | 0.5517 |

**数据量 3.09×，Macro-F1 +2.25pt，准确率 −1.20pt。**

## 结论

### 1. 提升是「类别均衡」换来的，不是整体变好

三档趋势完全单调：Macro-F1 一路升（0.4898 → 0.5008 → 0.5123），准确率一路降（0.5865 → 0.5793 → 0.5745）。

这是增强的典型副作用：合成样本让稀有类的决策边界变清晰（每类等权计算，小类提升直接抬高 Macro-F1），但稀释了头部类的判别特征（`治疗方法` 占 22%，accuracy 主要由它决定）。

### 2. 提升幅度落在噪声区间内

416 条验证集上，准确率的 95% 置信区间约 ±4.8pt，Macro-F1 量级相近。+2.25pt 单点看不显著，但**三个数据量点上单调递增**，方向上可信。

### 3. 过拟合显著提前

| 训练集 | epoch 1 | epoch 2 | epoch 3 | epoch 4 | 最优 |
|---|---|---|---|---|---|
| 1667 | 0.5285 | 0.4733 | **0.4367** | 0.4631 | epoch 3 |
| 3196 | 0.4775 | **0.4507** | 0.4542 | 0.5366 | epoch 2 |
| 5157 | **0.4479** | — | — | — | epoch 1 |

（表中为 val_loss）数据越多，第一个 epoch 越好，但最优 epoch 越来越早 —— 合成样本与原句高度相似，模型很快记住它们。

值得注意：5157 版本只跑了 **322 个优化器步**（1 epoch），却拿到最好的 Macro-F1；3196 版本跑了 **796 步**（4 epoch）反而更低。说明增益来自**数据多样性**，不是训练步数。

### 4. 质检是必需的一层

原始 3734 条变体里有 244 条（6.5%）必须丢弃：

| 问题 | 条数 | 实例 |
|---|---|---|
| 药名被替换 | 196 | 湿热痹胶囊→**四妙**胶囊；童康片→**通康**片；乌灵胶囊→**五灵**胶囊 |
| 数字被改 | 46 | 多为阿拉伯↔汉字转换的误判，保守丢弃 |
| 长度异常 | 2 | 超出原句 0.5–2.0 倍 |

医疗场景下错药名是硬伤，因此采用保守策略（宁可误杀）。

## 这个实验真正的价值

**它证明了瓶颈不在数据量。**

数据 3 倍，Macro-F1 仅 +2.25pt、准确率还降了 1.2pt。真正的瓶颈在标注本身：

- `方法` 类 recall 在三档里分别是 0.000 / 0.000 / 0.053 —— 模型几乎从未预测对；
- `定义 / 临床表现 / 治疗方法 / 方法` 四类语言线索高度重叠，占 45% 样本，`meta.json` 里 10 组标注冲突全部集中在这四类。

下一步该做的是**合并易混类别、统一标注口径、定向补 `方法` 类样本**，而不是继续生成同分布变体。

## 复现

```bash
# 1. 生成回译变体（需 LLM_API_KEY）
python data/augment_backtranslate.py --variants 3 --target 3950

# 2. 合并 + 写 provenance
python data/merge_augmented.py

# 3. 质量闸门（丢弃药名/数字漂移）
python data/audit_augmented.py --write

# 4. 训练（batch 2 是为了避免 8G 显存换页，等效 batch 仍为 16）
python llm_lora/train_lora.py --data train_aug_clean.json --tag aug5k --epochs 1 --batch_size 2 --grad_accum 8 --save_best

# 5. 评测
python llm_lora/eval_lora.py --adapter outputs/lora_adapter_aug5k_best --out outputs/lora_aug5k_pred.json
```

## 已知问题

- 5157 版本的训练集用了 `batch_size=2, grad_accum=8`（等效 batch 16，与原设置一致），因为 `batch_size=4` 在 8 G 显存上会触发 WDDM 换页，速度掉 10 倍以上。优化器步数因此与 3196 版本不同（322 vs 796）。
- 回译只做了「中→英→中」单一路径，没有做多语言往返（如中→日→中）或多次采样投票。
- 质检的药名提取基于剂型后缀正则，会误杀「脊灰糖丸→脊髓灰质炎糖丸」这类同药全称改写，估计误杀率 5–10%。
